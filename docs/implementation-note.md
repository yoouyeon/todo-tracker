# 할 일 옵시디언 플러그인 구현 노트

작성일: 2026-10-18  
상태: 읽기 전용 화면과 편집까지 구현, 옵시디언에서 직접 확인하는 단계

## 목표

`할일/`의 월별 Markdown 할 일 노트를 옵시디언 안에서 빠르게 확인하고 편집한다. 플러그인은 별도 데이터베이스를 만들지 않는다. 기존 월 파일이 유일한 데이터 원본이며, 사용자가 Markdown을 직접 편집해도 화면에 반영한다.

데스크톱과 모바일 옵시디언에서 모두 쓴다. `manifest.json`의 `isDesktopOnly`는 `false`로 둔다.

이 플러그인은 월 파일 한 개에 여러 할 일이 있으므로 본문 파싱과 항목 단위 수정은 별도로 구현한다.

## 기존 기록 형식과 불변 조건

- 대상 파일은 설정한 폴더 아래의 `YYYY-MM.md`이다. 기본 폴더는 `할일`이다. `AGENTS.md` 등은 읽지 않는다.
- 새 할 일은 **처음 하기로 한 날짜의 월** 파일에 넣는다. 이후 계획 날짜가 다른 달로 넘어가도 원래 파일에 남긴다.
- 항목 상태의 원본은 최상위 체크박스 `[ ]`(진행 중), `[x]`(완료), `[-]`(취소)다. 별도 `상태` 필드를 만들지 않는다.
- 각 항목의 `하기로 한 날`은 지금 하기로 한 날짜 하나다. 날짜를 바꾸면 이 줄만 고친다. 앞당기기, 미루기, 다른 달로 옮기기 모두 같은 동작이다.
- `처음 하기로 한 날`은 처음 계획한 날짜다. 없으면 `하기로 한 날`과 같다고 본다. 플러그인은 날짜를 처음 바꿀 때 원래 날짜로 이 줄을 한 번 적고, 그 뒤로는 건드리지 않는다.
- 목록의 `현재 계획 날짜`는 `하기로 한 날`이다. `오래 밀린 일`의 일수는 현재 계획 날짜와 관계없이 처음 하기로 한 날을 기준으로 계산한다.
- 날짜를 쉼표로 이어 적은 예전 형식(`하기로 한 날: 2026-10-05, 2026-10-12`)은 읽기 전용 항목으로 보여 주고, 처음 날짜를 `처음 하기로 한 날`에 따로 적도록 안내한다.
- 외부 `마감일`은 계획 날짜와 별도로 취급한다. `YYYY-MM-DD`와 `YYYY-MM-DD HH:mm`을 지원한다.
- 완료할 때 `완료한 날`, 취소할 때 `취소한 날`과 `이유`를 기록한다. 지난 날짜만 보고 자동 완료·취소하거나 날짜를 만들지 않는다.
- `분류`, `다른 이름`, `메모`와 플러그인이 모르는 필드는 편집 과정에서 보존한다.
- 월 파일의 frontmatter `월`은 파일 이름과 일치해야 한다. `미완료`는 해당 파일에 `[ ]` 항목이 하나라도 있는지 나타낸다. 본문 체크박스가 기준이다.
- 진행 중인 할 일을 모을 때는 현재 월뿐 아니라 과거 월 파일도 읽는다. 처음 계획한 날부터 달력 기준 7일 이상 지난 진행 중 항목(`최초 계획일 + 7일 ≤ 오늘`)은 `오래 밀린 일`로 표시한다. 단 현재 계획 날짜가 아직 오지 않은 `예정` 항목은 밀린 게 아니므로 표시하지 않고, `지난 계획`과 `오늘`에만 붙인다. 이것은 상태가 아니라 화면 계산 결과다.
- 같은 이름의 항목이 여러 개 있을 수 있다. 이름만으로 자동 병합하거나 특정 항목을 선택하지 않는다.

## 데이터 모델

파서는 화면에 필요한 정규화 모델과 원문 위치를 함께 반환한다.

```ts
type TaskStatus = "open" | "done" | "cancelled";

interface TaskRecord {
  sourcePath: string;
  line: number;
  sourceRange: { start: number; end: number };
  sourceText: string;
  title: string;
  status: TaskStatus;
  firstPlanned: string | null;
  planned: string | null;
  deadline: { date: string; time: string | null } | null;
  completedOn: string | null;
  cancelledOn: string | null;
  cancelReason: string | null;
  category: string | null;
  aliasText: string | null;
  memo: string | null;
  unrecognizedLines: string[];
  problems: { code: ProblemCode; message: string }[];
}

type ProblemCode = "checkbox" | "title" | "planned" | "date" | "duplicateField";
```

- `aliasText`는 `다른 이름`의 원문이다. `claude code 강의 part 3, 4`처럼 이름 안에 쉼표가 들어갈 수 있어서 쪼개지 않는다. 읽기 전용이고 검색에만 쓴다.
- `problems`가 비어 있지 않은 항목은 읽기 전용으로 보여 준다. 잘못된 날짜 형식, 알 수 없는 체크박스 기호, 비어 있는 제목, 없거나 날짜가 여러 개인 `하기로 한 날`, 겹치는 속성이 해당한다. 형식이 틀린 값은 버리고 나머지 필드만 읽는다. 원문은 `sourceText`에 남는다.
- `unrecognizedLines`는 모르는 속성 줄과, 첫 속성 줄보다 깊게 들여쓴 줄을 들여쓰기까지 그대로 담는다. 편집할 때 이 줄들은 건드리지 않는다.
- `line`은 항목 헤더 줄의 번호(0부터)다. `노트에서 열기`가 그 줄로 이동하는 데 쓴다.

`sourceRange`는 화면 표시 때의 참고 정보다. 저장할 때는 파일의 최신 본문을 다시 파싱하고, 선택한 항목의 원문과 위치를 대조한다. 원문이 바뀌어 같은 항목임을 확신할 수 없으면 덮어쓰지 않고 갱신 안내를 보여 준다. 영구 ID를 기존 노트에 일괄 삽입하지 않는다.

## 읽기와 갱신

1. 옵시디언 vault에서 설정 폴더의 월 파일을 찾는다.
2. 파일 본문을 읽고 frontmatter, 최상위 체크리스트, 들여쓴 속성 줄을 파싱한다. 본문이 잘못된 항목은 숨기지 않고 읽기 전용으로 표시해 원문을 열 수 있게 한다.
3. 모든 월 파일의 항목을 하나의 목록으로 합친 뒤 날짜, 상태, 분류에 따른 화면 모델을 계산한다.
4. 파일 생성·수정·이름 변경·삭제 이벤트를 구독한다. 관련 월 파일이 바뀌면 해당 파일을 다시 읽고 화면을 갱신한다. 날짜가 바뀌는 경우에도 날짜 기반 표시를 다시 계산한다.

화면은 저장소를 `useSyncExternalStore`로 구독한다. 할 일 항목은 frontmatter에 없으므로 메타데이터 캐시로 만들 수 없고, 본문을 직접 읽고 파싱해서 만든다.

## 쓰기 정책

- 화면의 수정 요청은 UI에서 바로 파일을 조작하지 않고 액션 계층으로 전달한다.
- 화면에서 새 할 일 추가, 완료·취소, 계획 날짜, 외부 마감일, 분류, 메모를 직접 편집한다. 취소 모달에서 이유를 받는다. `다른 이름`은 상세 정보에서 보여 주되 플러그인에서 편집하지 않고 원문을 보존한다.
- 액션 계층은 대상 월 파일에 `Vault.process()`를 호출한다. 콜백에서 **최신 파일 내용**을 다시 파싱하고 대상 항목을 확인한 뒤 필요한 체크박스 또는 속성 줄만 교체한다.
- 대상 항목은 최신 본문에서 `sourceText`가 같은 항목으로 찾는다. 그런 항목이 하나뿐이면 위치가 바뀌었어도 같은 항목으로 본다. 내용이 같은 항목이 여럿이면 줄 번호까지 같은 것만 고른다. 어느 쪽에도 해당하지 않으면 쓰지 않고 이유를 알린다.
- 읽을 수 있고 진행 중인 항목만 고친다. 끝난 항목과 `problems`가 있는 항목은 고치지 않는다.
- 파일 전체를 다시 쓰지 않고 바뀌는 줄만 고친다. 파일이 쓰는 줄바꿈(CRLF 또는 LF)을 새로 넣는 줄에도 그대로 쓴다.
- 같은 파일 수정에서 `미완료`를 본문 기준으로 다시 계산해 frontmatter에 반영한다. 다른 frontmatter 필드와 다른 할 일 항목, 알 수 없는 속성은 유지한다.
- 추가 입력에는 첫 계획 날짜가 필수다. 그 날짜의 월 파일에 항목을 쓴다. 파일이 없으면 `월`과 `미완료`가 있는 새 월 노트를 생성한다.
- 새 항목은 월 파일 안에서 첫 계획 날짜 순서를 유지하도록 넣는다. 같은 첫 계획 날짜의 항목이 있으면 그 묶음의 마지막에 넣는다.
- 사용자 입력 없이 비슷한 이름의 기존 항목과 새 항목을 합치지 않는다. 완전히 같은 이름의 진행 중 항목이 발견되면 기존 항목에 날짜를 추가할지 새 항목을 만들지 사용자가 선택하도록 한다.
- 쓰기 실패나 원문 충돌이 발생하면 화면에 이유를 알리고 노트를 열 수 있게 한다. 자동 재시도로 다른 항목을 수정하지 않는다.
- 완료는 오늘 날짜를 기본값으로 제시하고 사용자가 날짜를 바꿀 수 있게 한다. 취소는 취소 날짜와 이유를 입력받는다. 입력을 저장하기 전에는 상태를 바꾸지 않는다.
- 분류는 자유 입력이며, 할 일 노트에 이미 있는 분류 값을 제안 목록으로 보여 준다.
- 하기로 한 날은 지금과 같은 날짜로만 바꿀 수 없다. 그 날짜는 메뉴에서 비활성화하고, 입력창에서는 이유를 알린다. 처음 하기로 한 날은 바뀌지 않으므로 항목은 처음 계획한 달의 월 노트에 그대로 남는다.
- 새 속성 줄은 `처음 하기로 한 날`, `하기로 한 날`, `마감일`, `완료한 날`, `취소한 날`, `이유`, `분류`, `다른 이름`, `메모` 순서가 되는 자리에 넣는다. 모르는 줄과 더 깊게 들여쓴 줄은 건드리지 않는다. 마감일, 분류, 메모를 비우면 그 줄을 지운다.
- 속성 줄은 한 줄이라 제목, 이유, 분류, 메모에 든 줄바꿈과 연속 공백은 공백 하나로 줄여서 쓴다.
- 월 파일이 없으면 폴더까지 만들어서 새 월 노트를 쓴다. 만드는 사이 같은 파일이 생겼으면 그 파일에 한 번만 다시 시도한다.

## 화면과 상호작용

시안은 [`mockups/index.html`](../mockups/index.html)에 있다. 브라우저로 열어 휴대폰·데스크톱, 라이트·다크, 강조색, 가상 테마를 바꿔 볼 수 있다. 시안의 항목은 모두 예시 데이터다.

### 진입

- 리본 버튼과 명령어로 독립 `ItemView`를 연다. 이미 열려 있으면 기존 탭으로 이동한다.
- 별도의 달력이나 칸반을 두지 않는다.

### 화면 구성

위에서 아래로 다음 순서로 놓는다.

1. 머리말: 제목, 오늘 날짜와 `오늘 N개 중 M개 완료` 요약, `새 할 일` 버튼(`mod-cta`). 휴대폰에서는 버튼을 아이콘만 남긴다.
2. 요약 카드 4개: `지난 계획`, `오늘`, `예정`, `기록`과 각 개수. 카드는 탭 역할을 한다. 카드를 누르면 그 묶음만 보이고, 같은 카드를 다시 누르거나 `전체 보기`를 누르면 세 묶음(지난 계획·오늘·예정)이 모두 보인다. 휴대폰에서는 카드를 한 줄에 작게 놓고 이름과 숫자만 보여 준다.
3. 묶음: 아이콘, 이름, 개수, 접기 버튼이 있는 머리글과 얇은 구분선. `오늘`과 `예정` 머리글에는 그 날짜(오늘, 내일)를 미리 채운 추가 버튼을 둔다.
4. 아래에 떠 있는 도구 바: 검색, 마감 필터(`임박·지남`), 분류 필터. 스크롤 영역 안에서 `position: sticky`로 붙인다.

### 묶음 기준과 정렬

- 진행 중 항목은 `현재 계획 날짜`에 따라 `지난 계획`(오늘 이전), `오늘`, `예정`(내일 이후) 중 한 곳에만 놓는다. 지난달 기록의 진행 중 항목도 포함한다.
- `지난 계획`: 오래 밀린 일을 위에 모으고 최초 계획일이 오래된 순으로 놓는다. 그다음 마감이 지났거나 임박한 항목, 나머지는 현재 계획 날짜 순이다. 오래 밀린 일이 있으면 머리글 아래에 개수와 기준을 안내한다.
- `오늘`: 마감이 지났거나 임박한 항목을 먼저 놓는다. 오늘 완료한 항목은 목록 끝에 취소선으로 남긴다.
- `예정`: 현재 계획 날짜 순이다.
- 외부 마감일이 지났거나 3일 이내(오늘 포함)이면 `임박·지남`으로 본다. 마감 필터는 계획 날짜와 무관하게 적용한다.
- `problems`가 있는 항목은 묶음에 넣지 않고 화면 맨 아래 `확인이 필요한 항목`에 놓는다. 항목마다 이유와 `노트에서 열기`를 보여 준다. 월 파일 전체의 문제(frontmatter `월`·`미완료` 불일치 등)도 같은 묶음에 경로와 함께 적는다. 요약 카드 개수에는 넣지 않는다.

### 항목 행

- 한 줄에 원형 체크박스, 제목, 오른쪽 부가 정보를 놓는다. 제목이 길면 말줄임하고, 펼치면 전체를 보여 준다.
- 부가 정보는 오래 밀림 칩(`N일째`), 마감 칩, 현재 계획 날짜다. `오늘` 묶음에서는 날짜를 생략하고, `예정` 묶음에서는 요일을 붙인다.
- 체크박스를 누르면 완료 모달을 연다.
- 데스크톱에서는 행에 마우스를 올리거나 행을 펼치면 부가 정보 자리에 `완료`, `날짜`, `⋯` 버튼을 보여 준다.
- `⋯` 버튼, 오른쪽 클릭, 길게 누르기로 옵시디언 `Menu`를 연다. 메뉴 항목은 오늘 하기, 내일 하기, 날짜 선택, 완료로 기록, 상세 보기, 편집, 노트에서 열기, 취소다. 지금 하기로 한 날과 같은 날짜는 비활성화한다.

### 상세 정보

- 항목을 누르면 목록 안에서 그 자리에 펼친다. 다시 누르면 접는다.
- 계획 날짜(바꾼 적이 있으면 처음·현재를 함께 표시), 처음 계획부터 지난 일수, 마감일, 완료·취소 날짜와 이유, 분류, 다른 이름(읽기 전용), 메모, 원본 파일을 보여 준다.
- 버튼은 편집, 노트에서 열기, 취소다. 휴대폰에는 행 버튼이 없으므로 완료와 날짜 바꾸기도 상세에 넣는다.
- 마감일·분류·메모는 편집 모달에서 수정한다. 완료·취소·날짜 선택·새 할 일도 옵시디언 `Modal`로 받는다.

### 기록

- `기록` 카드를 누르면 완료·취소 항목을 처리한 날짜 기준으로 최근 것부터 묶어 보여 준다.
- 상태(전체·완료·취소)와 월은 옵시디언 기본 드롭다운으로 고르고, 도구 바의 분류 필터와 제목·다른 이름 검색을 함께 쓴다.

## 스타일 정책

- 플러그인 CSS는 옵시디언 테마 변수만 쓴다. 색, 글자 크기(`--font-ui-*`), 둥글기(`--radius-*`), 간격(`--size-*`), 그림자(`--shadow-s/l`), 폰트는 직접 정하지 않는다. 원 모양을 만드는 `border-radius: 50%`는 예외다.
- 플러그인 자체 색을 쓰지 않는다. 오래 밀림, 마감 지남·임박 같은 의미는 아이콘, 글자, 테두리 칩, 굵기로 나타낸다. 상태 색 변수(`--color-red`, `--color-orange` 등)로 의미를 표시하지 않는다.
- 강조색은 `mod-cta` 버튼, 포커스, 선택된 요약 카드처럼 옵시디언 기본 요소와 선택 상태에만 쓴다. 경고는 옵시디언 기본 `mod-warning`과 `--text-error`를 쓴다.
- 버튼, `clickable-icon`, `dropdown`, `Menu`, `Modal`, `Notice`는 옵시디언 기본 요소를 쓰고 따로 꾸미지 않는다. 눌러서 동작을 실행하는 요소는 `button`을 쓰고 모양은 테마에 맡긴다. `전체 보기`가 그렇다.
- 항목 제목처럼 본문 글자로 보여야 하는 클릭 요소는 `button` 대신 `role="button"`과 `tabindex`를 준 일반 요소로 만들고 Enter·Space를 직접 처리한다. 테마가 모든 `button`에 테두리와 그림자를 입히기 때문이다.
- 휴대폰 화면 조정은 옵시디언이 body에 붙이는 `is-mobile`, `is-phone` 클래스로 한다.

## 코드 구성 제안

```text
src/
  main.ts                 플러그인 등록, 명령어, 쓰기 액션 연결
  TaskView.tsx            옵시디언 ItemView와 React 마운트
  data/parseMonthNote.ts  월 파일 본문 파싱
  data/editMonthNote.ts   항목 수정과 frontmatter 동기화
  data/taskStore.ts       월 파일 색인과 변경 구독
  logic/dates.ts          날짜 검증, 오래 밀림, 일정 분류
  logic/selectors.ts      화면용 목록과 정렬
  ui/                    화면, 행, 상세, 모달
  settings/              폴더 등 최소 설정
  styles/                옵시디언 테마 변수만 쓰는 스타일
```

TypeScript, React, esbuild, Vitest를 사용한다. UI 문구는 한곳에 모으고, 날짜·파서·수정 로직은 Obsidian 런타임 없이 테스트할 수 있는 순수 함수로 만든다.

## 구현 순서와 확인 기준

1. 파서와 날짜 로직: 실제 월 파일 형식을 읽고 처음·현재 계획 날짜, 마감일, 같은 제목의 항목을 구별한다. 낯선 속성과 형식 오류를 잃지 않는다.
2. 읽기 전용 화면: 여러 월 파일의 진행 중 항목과 기록을 보여 준다. Markdown 직접 수정이 화면에 반영된다.
3. 안전한 편집: 추가·상태 변경·날짜 변경·세부 필드 편집을 확정된 범위까지 구현한다. 원본 충돌과 `미완료` 갱신을 검증한다.
4. 사용성 점검: 휴대폰과 좁은 데스크톱 창, 라이트·다크 테마와 다른 커뮤니티 테마, 키보드 조작, 플러그인 재시작, 월 경계를 확인한다.

테스트에는 사용자의 할 일 노트 원본을 직접 수정하지 않고, 구조가 같은 테스트 파일을 사용한다. 실제 vault 적용은 빌드와 테스트를 통과한 뒤 확인한다.

## 확정한 화면 정책 요약

- 기본 화면: 요약 카드 4개와 `지난 계획`·`오늘`·`예정` 묶음. 카드가 탭 역할을 한다.
- 현재 계획 날짜: `하기로 한 날`. 처음 날짜는 `처음 하기로 한 날`에 한 번만 남긴다.
- 지연 표시: 현재 계획 날짜가 지난 진행 중 항목은 모두 `지난 계획`에 놓는다. 최초 계획일부터 7일 이상 지난 항목은 위에 모으고 `N일째` 칩을 붙인다. `오늘` 항목에도 칩을 붙이고, `예정` 항목에는 붙이지 않는다.
- 마감 임박: 외부 마감일이 지났거나 3일 이내.
- 상세: 그 자리에서 펼친다.
- 빠른 동작: 체크박스로 완료, `⋯`·오른쪽 클릭·길게 누르기로 메뉴. 날짜 바꾸기는 오늘·내일·날짜 선택.
- 오늘 완료한 일: `오늘` 묶음 끝에 취소선으로 남긴다.
- 플러그인 편집: 추가, 완료, 취소, 계획 날짜, 마감일, 분류, 메모. `다른 이름`은 읽기 전용이다.
- 완료·취소 탐색: `기록` 카드의 검색과 필터.
- 스타일: 옵시디언 테마 변수만 쓰고, 의미는 색이 아니라 아이콘·글자·칩으로 나타낸다.
